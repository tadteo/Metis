# Continuing this project

Read `docs/development.md` before changing code. It defines the plan → isolated branch/worktree →
implementation → tests → independent review → commit → merge sequence and completion evidence.
Start from Git status/history and the relevant persisted task plan, not an earlier conversation.

For scientific behavior, read `docs/paper-spec.md` and the component row in `docs/fidelity.md`.
For module boundaries or runtime changes, read `docs/architecture.md` and the relevant guide
(`docs/coding-harness.md`, `docs/paper-orchestra.md`, or `docs/reproducibility.md`). Follow
`CONTRIBUTING.md` for validation and public-artifact rules. A missing linked guide is an unfinished
integration; preserve that fact until implementation and validation close it.

Preserve all scientific attempts, failed commands, rejected hypotheses and negative measurements.
Only accepted measured evidence can promote a candidate. Demo output is synthetic. A successful
software test is not evidence of research-quality parity with ScientistTwo.
