Where experiments run
      
The controller runs on the location selected in Connections. Docker uses that host's Docker engine; local means that host, even over SSH. The model provider generates code; this compute environment executes it.

      

        
        
Docker isolates each command in a container with no network, a read-only root and a writable experiment directory. Prepare an image with dependencies; configure read-only datasets under Data & protocol.

        
Slurm submits jobs to cluster compute nodes. The controller needs scheduler tools, and nodes need the runtime and shared experiment storage. Slurm schedules resources; this backend does not add container isolation.

        
Local runs directly with the controller's OS user permissions and installed dependencies. It provides no container isolation or CPU, memory or GPU allocation limits.

        
        
        
        
Per-job Docker limits or Slurm requests, not a total run allocation.

        
        
        
        
      

      
Experiments within one research run currently execute one at a time, including seed repeats. Each experiment has a private source snapshot and working directory; these are not Git worktrees. Separate runs may overlap, without a shared resource quota.

      
Manuscript generation uses separate PaperOrchestra execution settings under Advanced JSON. Changing this backend does not change the writer backend. Saved runs keep their recorded configuration.
