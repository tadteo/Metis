# Set model credentials from Metis

Base: `d890295`. Source: user asks to enter an API key securely in Metis and to remember it in the host credential vault when supported. The existing settings form accepts only an environment variable name.

Boundary: add a separate authenticated credential endpoint and a password control to Model access. Resolve provider keys from Metis session memory, then the host vault, then the existing environment variable; never copy a key into run settings, artifacts, logs, experiment subprocess environments, or browser storage. Trusted model adapters and the pinned writer worker receive only their explicitly configured key in a minimal environment. Use only supported OS credential backends; explicitly offer session-only storage when the vault cannot be used. The named credential remains the stable lookup reference in settings. No provider request occurs while saving or checking a key.

Acceptance: save, status and clear work without returning a key; a vault key survives server restart, a session key does not; missing vault support does not create a plaintext file; invalid values are rejected without echo; preflight and provider use the same resolver; model access explains local versus remote host storage; stale field contents are cleared; existing environment-based setups continue working. Verify auth and origin guards, key redaction, focused Python/browser checks, repository gates, independent review, visual and keyboard behavior, commit and merge.

## Evidence to date

The OS vault integration uses pinned `keyring==25.7.0` (MIT) and only its built-in macOS Keychain, Windows Credential Locker, Secret Service and KWallet backends; other backends are treated as unsupported. On this development Mac, backend inspection found `keyring.backends.macOS.Keyring` with positive priority. No real credential was entered or read during tests or visual inspection. All tests use synthetic values and a mocked vault. `uv lock` and a clean `uv sync --frozen --group dev --extra evaluation` completed for the isolated worktree. The first sandboxed `uv lock` attempt failed because the shared uv cache was not writable; the approved rerun completed.

Visual and keyboard journey: a disposable loopback console with private temporary state showed Workspace settings opening directly at Model access. At 1280×720 in charcoal and cream, the key field, storage choice, Save action and source status were readable without scrolling; model/address and environment alternatives remained reachable in disclosures. At 390×844, the same controls and disclosures were reachable by scrolling the dialog without horizontal overflow, while the actions remained available. The password field was focused on entry. Browser logic confirms it clears immediately on Save and on Escape/close; no model request occurs during setup. The disposable tab and server were closed. No paid provider request or real key was used.

Independent review findings and their resolutions are recorded in `docs/reviews/in-app-credentials.md`. The host vault protects at the OS-user boundary; explicitly enabled local generated-code execution shares that user's access and may read the vault. This limitation is visible in the local execution control and documented in architecture and usage.
