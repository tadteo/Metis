# ScholarPeer and literature evidence

Source audit: 2026-09-29. The implementation uses the **published Appendix G templates** from [ScholarPeer, arXiv:2601.22638v2](https://arxiv.org/abs/2601.22638v2), extracted from the [versioned author source archive](https://arxiv.org/src/2601.22638v2). The adjacent `src/autoresearch/assets/scholarpeer/manifest.json` records archive/source/individual-prompt SHA-256 hashes, authors, transformations and license. The templates retain the authors' **CC BY 4.0** license, with attribution in `NOTICE.md`; runtime code is separately licensed by this repository.

The paper, [Google's publication record](https://research.google/pubs/scholarpeer-a-multi-agent-framework-for-automated-peer-review/), and [Google's announcement](https://research.google/blog/improving-the-academic-workflow-introducing-two-ai-agents-for-better-figures-and-peer-review/) were inspected. They link ScholarPeer's paper but no callable official source/API release. Searches of the Google Research and Google DeepMind GitHub namespaces did not locate a release. The similarly named [Open ScholarPeer repository](https://github.com/amirkiarafiei/open-scholar-peer) explicitly identifies itself as a community implementation and is not used as official source. This is a bounded release audit, not proof that an undisclosed service cannot exist.

## Implemented reconstruction

`review_context` runs structured claims/method/evidence extraction, independent initial literature retrieval, **three expansion rounds**, chronological historian and independent baseline scout, novelty and technical question generators, and **ten separate question-answer calls** (five per criterion). Synthesis uses G.8 in the existing reviewer panel. The total is 19 investigation calls plus synthesis, matching Appendix D.1's approximately 20-call configuration. The five/five split is a disclosed reconstruction because D.1 states ten total; all counts are recorded/configurable.

Every call receives the applicable original template with its named placeholders rendered. Original source text is immutable and hash-checked. The runtime adapter wraps prose/JSON/list outputs in `AgentOutput`, retaining original structured findings in `structured`, questions in `plans`, supporting source IDs, missing baselines, answers, individual outputs and the publication cutoff. Invalid structured extraction, missing questions and nonexistent novelty evidence IDs trigger bounded semantic repairs, followed by one configured frontier-model escalation before failing explicitly. Failed outputs remain in the review record. Domain analysis and extracted references accumulate across the initial review and all expansions, rather than retaining only the final expansion. The G.8 few-shot placeholder is retained as empty because examples for that placeholder are not supplied in Appendix G.

[Section 3.1](https://arxiv.org/html/2601.22638v2#S3.SS1) requires top-tier proceedings/arXiv and publication cutoffs. The runtime filters retrieved evidence accordingly, retains excluded records/reasons, excludes undated papers and post-cutoff revisions, and freezes an unspecified cutoff to the run's creation date. Earlier arXiv versions are not silently replaced by a later version's abstract/full text. This conservative handling may reduce coverage and is visible in the report.

The synthesis profile supplies ICLR 2025 guidance and the ScientistTwo 1–10 recommendation convention; an alternative NeurIPS 2025 profile retains its native 1–6 scale and four dimension scores. Sources: [ICLR reviewer guide](https://iclr.cc/Conferences/2025/ReviewerGuide), [NeurIPS review form](https://neurips.cc/Conferences/2025/ReviewerGuidelines). These are simulated recommendations, **not acceptance probabilities**. Held-out review remains a distinct final-only role and does not feed the improvement loop.

## Retrieval adapters and limitations

`Literature` provides independently callable Crossref, Semantic Scholar and arXiv adapters. Exact response bodies, query parameters, provider statuses, response hashes, timestamps, publication dates, source records, abstracts and inspected full text are retained. Model-facing views omit duplicate raw transport records while preserving inspected content, coverage limits and provenance hashes; complete transport records remain in the persisted artifacts. All shared DOI/arXiv/URL aliases jointly deduplicate merged results, including papers linked by a cross-provider bridge record; response bodies retain provider-specific duplicates. Full text currently uses arXiv HTML, when available; other open-access PDF locations are retained for inspection but not fetched as arbitrary remote URLs. Unavailable HTML, response size ceilings, truncation and rate limits are recorded rather than represented as inspected content.

API references: [Crossref REST documentation](https://www.crossref.org/documentation/retrieve-metadata/rest-api/), [Semantic Scholar Academic Graph API](https://api.semanticscholar.org/api-docs/graph), [arXiv API manual](https://info.arxiv.org/help/api/user-manual.html). arXiv calls serialize at least three seconds apart; requests use timeouts, fixed endpoints, no redirects and a 4 MB response ceiling. Search snippets are untrusted data and never executable instructions.

The original Google Search-enabled LLM is replaced with explicit scholarly retrieval adapters, an engineering substitution requiring capability evaluation. Abstract/API coverage is not equivalent to web-scale search. The G.2 target of 30–50 significant papers is explicitly checked as a coverage deficit if unmet. A minimum of three independent inspectable papers is only an eligibility gate for an assessment, **never evidence of exhaustive novelty**. No retrieved sources, two metadata references, failed providers or disabled search cannot establish novelty. The runtime explicitly overrides G.7's instruction to infer high novelty from no prior art, as required by the user's stronger evidence standard.

`docs/evidence/literature-live-smoke.json` records actual public API smoke outcomes where present. Unit/contract tests in `tests/test_literature.py` and `tests/test_review.py` check adapters, cutoff leakage, exact response retention, source provenance, full-text truncation, prompt hashes, published call counts and invalid output rejection. They establish implementation behavior, not autonomous research or review-quality parity.
